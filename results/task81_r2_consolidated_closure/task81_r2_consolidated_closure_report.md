## §2 — Complete order identity + state (RCA + fix)

**Reproduced** (`test_task81_r2_reconcile_identity.py`, production
`reconcile()`): (1) an internally **filled** order that the broker still
lists open, while position quantities agree → pre-fix `matched=True`;
(2) a known broker id carrying the **wrong `client_order_id`** → pre-fix
`matched=True`. Pre-fix reproduction: **32 failed / 12 passed** against
`d8e530e` (`raw_test_output/prefix_reproductions.txt`).

**Root cause:** `_classify_broker_open_order` (R1) exempted `filled`
internal orders from the terminal-vs-open contradiction check ("commonly
broker eventual consistency"), and `_fields_agree` checked symbol/side/qty
but never the row's `client_order_id`.

**Fix (one coherent contract in `talonx_piv/lifecycle.py`):**
- `_verify_broker_order_row` resolves a broker OPEN order to exactly one
  durable intent by **both** broker id and `client_order_id`. Conflicting
  ids → `CONTRADICTION`; an id match whose `client_order_id` ≠ the
  intent's → `CONTRADICTION`.
- **No eventual-consistency exemption:** any terminal-vs-open contradiction
  — including a locally `filled` order — is `CONTRADICTION`.
- Full field consistency: symbol / side / requested qty / cumulative
  filled qty; an impossible cumulative fill (> requested) or a regressed
  `filled_qty` → `CONTRADICTION`. Missing/malformed required fields →
  `MALFORMED` → counted as an incomplete read (never an accepted match).
- **Reverse direction:** every internally-outstanding order must have a
  verified current disposition — present in `open_orders()` by id,
  refreshed to terminal this pass, or a recorded read failure — otherwise
  `orders_missing_from_broker_list` (a transient two-read inconsistency
  that blocks and is retried, never a clean pass).
- **Position agreement never overrides order disagreement.**
- `_extract_order_update_fields` — one parse/validate function shared by
  `_resolve_unconfirmed_orders`, `_resolve_uncertain_submissions`,
  `_refresh_non_terminal_orders` (now returns `(failures,
  unresolved_ids)`).
- Durable BUY block persisted in `reconciliation_flags`
  (`lifecycle_state.json`) — survives restart; clears only on a complete
  + consistent pass.

## §3 — Real orphan recovery (production code only)

`_promote_orphan_order_intents()` folds an orphan `ORDER_INTENT` (a
persisted intent with **no** recorded broker order) into
`SUBMIT_FAILED_UNCERTAIN` at the top of `reconcile()`, so the audited
production machinery handles it end to end:

- discovery by the stable `client_order_id`
  (`_resolve_uncertain_submissions` → `broker.find_order_by_client_id`);
- adoption **only** on an exact match (`_order_response_matches_intent`),
  applying the real status — pending / partially filled / filled /
  terminal — with fill timing, the exit plan and actual holdings recovered
  (`test_orphan_recovery_matrix`);
- `operator_resolve_uncertain_submission` for an independently-verified
  non-submission (explicit confirmation + audit reason; refuses
  wrong-state / unknown / already-resolved);
- no blind resubmission; no timeout/count-based "never existed";
  restart-safe; idempotent.

The R1 tests that resolved an orphan by editing `.status` directly now use
the production operator method.

## §4 — Validate before mutating accounting (RCA + fix)

`_validate_broker_update(order, status, filled_qty, fill_price)` runs at
the **top** of `apply_broker_update`, before `previous_filled_qty` /
`previous_status` are even captured. It refuses:
unrecognised Alpaca status; non-finite / boolean / negative `filled_qty`;
non-finite / non-positive `fill_price`; `filled_qty > the intent's
requested quantity`. A refused update mutates nothing and emits
`BROKER_ERROR: BROKER_UPDATE_REJECTED_*` — so a contradictory response
cannot poison an order's terminal status or its filled-qty high-water
mark. Genuine positive deltas, prior exits/P&L, protective levels, intent
linkage and the exit latch are preserved; duplicate/stale responses stay
idempotent. The full production scenario (partial BUY → protective close →
later BUY fill → restart → remaining protective exit) is covered, as is
"reconciliation block never suppresses SELL / shadow / monitoring / EOD"
and "unknown exposure SELL fails visibly".
