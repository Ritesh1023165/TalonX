# DETERMINISTIC TEST DATA — NOT MARKET DATA

Three synthetic 1-minute OHLCV datasets live here. **None of them
represent real AAPL price action, any real symbol, or any real market
performance.** Do not use them for claims about TalonX's real-world
profitability — they are integration-test fixtures only. All are
deterministic (fixed-seed, same output every time they're regenerated)
and exist purely to exercise `talonx_backtest` end to end without
needing real historical data.

| File | Purpose | Expected result |
|---|---|---|
| `sample_AAPL_1m.csv` | **Smoke-test / validation dataset.** Proves data loading, data-quality validation, and report generation work — nothing more. | **Zero trades** (every candidate signal is rejected on confluence) — this is the CORRECT, expected outcome, not a bug. |
| `sample_AAPL_trade_1m.csv` | **Trade / execution / reporting dataset.** Specifically engineered to produce a real signal that clears every FROZEN production gate (confluence ≥ 2, R:R ≥ 1.5) naturally — no threshold was relaxed to make this happen. | **Exactly one executed trade**, exiting via `TARGET`. Populates `trades.csv`, `equity_curve.csv`, and the HTML report's trade metrics. |
| `sample_multi_trade_1m.csv` | **Multi-scenario execution/statistics dataset.** Three independent synthetic symbols (`TSTW`/`TSTL`/`TSTE`), each a separate deterministic scenario, all through the same unmodified `QuantConfig`. | **Three executed trades**: `TSTW` exits `TARGET` (win), `TSTL` exits `STOP` (loss), `TSTE` exits `END_OF_SESSION` (win, via the real 15:50 ET EOD-flatten sweep). Gives a real win+loss mix — profit factor, average loss, drawdown, and cumulative R are all non-degenerate. |

Together they exercise the engine through the zero-trade path, a single
winning trade, and a full win/loss/EOD-flatten mix — see
`tests/test_backtest_sample_data.py`.

```
clone repository
    ↓
run sample_AAPL_1m.csv          -- verify installation, zero-trade path
    ↓
run sample_AAPL_trade_1m.csv    -- verify execution/reporting, single-trade (TARGET) path
    ↓
run sample_multi_trade_1m.csv   -- verify TARGET + STOP + EOD-flatten paths, and
                                    aggregate win/loss statistics
    ↓
verify report generation for all three
```

**Do not** draw any conclusion about the TalonX strategy's real-world
performance from any of these datasets.

## Format

All three files use **naive** timestamps (no timezone suffix)
representing **America/New_York local time** — run all three with
`--tz America/New_York`. `sample_multi_trade_1m.csv` carries its own
`symbol` column (three tickers in one file), so it needs `--symbols`
instead of `--symbol`:

```powershell
python -m talonx_backtest --data examples\data\sample_AAPL_1m.csv --symbol AAPL --tz America/New_York --out results\sample
python -m talonx_backtest --data examples\data\sample_AAPL_trade_1m.csv --symbol AAPL --tz America/New_York --out results\sample_trade
python -m talonx_backtest --data examples\data\sample_multi_trade_1m.csv --symbols TSTW,TSTL,TSTE --tz America/New_York --out results\sample_multi
```

See [`docs/backtesting.md`](../../docs/backtesting.md) for why `--tz`
matters and what each output file means.

## Regenerating these files

All three are generated by short, deterministic scripts (no unseeded
randomness) — see `docs/backtesting.md`'s "Sample data" section for the
generation approach for each, including why the trade datasets need
~8 trading days of quiet pre-roll (the 200-bar / 15-minute HTF trend
gate needs that much regular-session history before it can produce a
non-`None` `htf_sma_200`), how each signal bar was calibrated to clear
confluence and R:R under the exact, unmodified production `QuantConfig`,
and how `sample_multi_trade_1m.csv`'s three symbols each reuse the same
proven signal setup with a different post-entry price path (continued
recovery → `TARGET`; a decline back through the stop level → `STOP`;
a bounded drift held between stop and target until the 15:50 ET
EOD-flatten sweep → `END_OF_SESSION`).

`sample_multi_trade_1m.csv` was regenerated in Task 81-R2 (2026-08-29) by
`scripts/gen_sample_multi_trade_1m.py`: it reuses the exact known-good bar
sequence of `sample_AAPL_trade_1m.csv` through its entry bar, then appends
the three per-symbol post-entry paths above. The strategy was not touched.
All synthetic outcomes: TEST_FIXTURE_ONLY — NOT ALPHA EVIDENCE.
