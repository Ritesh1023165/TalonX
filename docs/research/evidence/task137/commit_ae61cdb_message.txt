Five concrete findings from Task 136's evidence review, each investigated
and closed with a bounded, demonstrated fix:

1. EOD "PARTIAL" status is a standing, permanent condition for this
   deployment (piv_paper is intentionally never checked -- PIV/Alpaca is
   opt-in-only and never wired up), not evidence of a real problem, so
   eod_reconciled_today could never become true here even on a fully
   correct, on-time reconciliation. New talonx_ops.eod_reconciliation.
   reconciled_to_available_scope() distinguishes "PARTIAL solely because
   piv_paper is NOT_CHECKED, no mismatches, everything else CHECKED" from
   a genuinely broken/incomplete reconciliation -- exposed as a SEPARATE,
   explicitly-named signal (eod_reconciled_today_available_scope /
   today_reconciled_available_scope) in supervisor.py and authoritative_
   read_model.py, never silently reclassifying the existing strict field.

2. Deferred-lookup SATURATION (not merely "one failing row doesn't stop
   the rest of an already-selected batch", already covered): reproduced
   with a bounded selection `limit` entirely filled by rows whose lookup
   always raises -- a valid, eligible row sitting behind them in band/
   enqueue order was never selected at all, on any cycle. Fixed: a DEFER
   outcome now writes a bounded, fixed backoff (_DEFER_BACKOFF_SECONDS=
   30s) to the row's own next_retry_at_utc -- the SAME column/mechanism
   pending() already filters on -- so a permanently-failing row stops
   monopolizing its slot after a short window, while `state` itself is
   never touched (not terminal, fully recoverable, exactly-once on
   success). The bulk expire_stale() sweep deliberately does NOT filter
   on next_retry_at_utc itself (that column is shared with the UNRELATED
   send-attempt backoff mark_failed() sets; filtering the age sweep on it
   would let a row merely awaiting a send retry escape an age expiry it
   still needs) -- it still benefits by writing the same backoff if it
   reaches a failing row first.

   substituting one for the other). checkpoint.py's capture() determines
