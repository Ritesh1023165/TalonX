fix(ingest): Task 140 -- require genuine supported evidence before an immediate push

Closes the stricter content requirement introduced after Task 138's own
tests were written: classify_disposition previously trusted a
recognized substantive REASON CODE's mere presence
(SUBSTANTIVE_REASON_CODES membership, or a buy-cluster's bare kind
check) as sufficient justification for IMMEDIATE -- exactly the
"document-change score/reason code" and "count of insiders" bypass the
newer requirement explicitly forbids as a SOLE justification.

talonx_ingest/intelligence/delivery/notification_policy.py:
- classify_disposition's signature changes from `reason_codes` (bare
  code strings) to `reasons` (the significance engine's own full
  SignificanceReason objects) -- eligibility now validates that a
  qualifying code's OWN `description` field is genuinely populated
  (rules.py already bakes real facts into every description at
  generation time -- a percentage, a dollar figure, an owner count --
  never invented here, only read and validated). A code present with no
  genuine supporting text falls through to DIGEST, content-gated, never
  trusted on the code alone, never suppressed either.
- New `DispositionDecision.evidence_text` field carries the SPECIFIC
  qualifying fact sentence (the reason's real description, or -- for a
  buy cluster -- built directly from the InsiderCluster's own
  distinct_owners/window_calendar_days/transaction_count/total_value
  fields, never a bare presence/count claim).
- CRITICAL band (still always IMMEDIATE per the engine's own structural
  floor) now also carries real evidence_text drawn from its own highest-
  point reason, so a CRITICAL card's message shows a genuine fact too,
  not just a band label.

talonx_ingest/intelligence/service/enrichment.py: FIXES A CONFIRMED BUG
found while implementing this -- `disposition_reason=decision.reason`
was passing the INTERNAL POLICY-AUDIT string ("HIGH band with a
substantive trigger present: [CODE]") into the renderer, which
render_concise's own docstring claimed (incorrectly) was already the
"specific substantive trigger" text. Fixed to

hidden purely to stay at 5 lines.
